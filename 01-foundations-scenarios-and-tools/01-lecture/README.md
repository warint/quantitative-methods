# Session 01 — First half (~90 min)

# The syllabus

> **What this course asks of you, what it gives you, and how you will be judged.**

---

This session is not a lecture. There is no mathematics in it. The first half walks through
[`SYLLABUS.md`](../../SYLLABUS.md) in full, and you should arrive having read it — the ninety minutes
are for the questions it raises, not for reading it aloud.

The mathematics begins in Session 02.

---

## 1.1 What the course is

Twelve sessions, each 90 minutes of teaching and 90 minutes of group work.

Every method is **derived before it is used**, and every result is produced on your own machine
with open tools. Nothing in this course requires an API key, a subscription, or an internet
connection during a practice.

The organising question, in one line:

> **When can a number about the past be used to make a claim about the future?**

## 1.3 The ten projects

Ten groups of three. Five fixed angles, two groups each, at different units of analysis. Angles are
**fixed for the semester** so that expertise accumulates; the weekly theme rotates so each method
answers something real.

| Angle | Owns |
|---|---|
| **A** Compute & energy | electricity prices, generation mix, industrial demand |
| **B** Work & skills | employment by occupation, earnings, task exposure |
| **C** AI adoption | enterprise AI use, barriers, R&D, productivity |
| **D** Trade & dependence | bilateral flows in semiconductors, equipment, robots |
| **E** Policy language | ECB, EUR-Lex, national strategies |

Full detail, including your group's allocation: [`RESEARCH-MANDATES.md`](../../RESEARCH-MANDATES.md).

## 1.5 How individual work is separated from group work

Four mechanisms, three of which cost you nothing if you are doing the work.

| Mechanism | When |
|---|---|
| **Random presenter draw** | every practice session — the two-minute report is given by a member drawn live |
| **Git contribution report** | automatic — commits, share, weeks active |
| **Everyone pushes** | every practice session — all three members commit from their own machine |
| **Confidential peer ratings** | once, at term end |

A mark is reduced only when **two independent records agree**. One signal opens a conversation; it
does not move a mark.

The **oral** in the final exam is the fourth and strongest: fifteen minutes, alone, on your own
paper and on the course. Full policy: [`GROUP-ASSESSMENT.md`](../../GROUP-ASSESSMENT.md).

## 1.6 The standing rules

**On data.** Never committed. Download once, cache as parquet, read from the cache. Record
provenance. Every practice session must run offline.

**On reproducibility.** One virtual environment, one committed `requirements.txt`, every seed set
explicitly. If your result does not reproduce from a clean clone, it does not reproduce.

**On the local LLM.** Use it freely, as a sparring partner and never as an oracle. Ask it to argue
against you. Verify every factual claim. Every practice session deliverable documents at least one instance
where you caught it being wrong or unverifiable. You are never penalised for using it; you are
penalised for using it uncritically.

**On claims.** When you report a number, be able to say in one sentence where it came from and what
would falsify it.
